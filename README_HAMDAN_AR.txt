HAMDAN EDITION - VERSION REORGANIZED FOR GITHUB
===============================================
هذا المشروع المصدري جمعنا فيه تعديلات: توجيه أعداء المهمة للكلاينت،
فشل المهمة عند موته عبر فحص الموت الأصلي، مزامنة علامات مهمات القصة،
تخفيف أنيميشن الركض، وتصميم واجهة حمدان.

مهم جداً: لم يُبنَ dinput8.dll في هذه البيئة ولم تُختبر التعديلات داخل اللعبة.
اختبارات المنطق وحدها ليست إثباتاً أن الميزات تعمل في جميع المهمات.
تغيير أنيميشن الركض لا يثبت أن سرعة انتقال اللاعب داخل اللعبة صارت أقل.

سبب المشكلة السابقة: ملف .github كان داخل VCCoop_Hamdan_GitHub_Ready
بدلاً من جذر المستودع. في هذه النسخة يظهر .github بجانب src مباشرة.
المستودع الحالي على GitHub قد يظل فيه المجلد القديم؛ ملف البناء الجديد
يكتشف الاثنين تلقائياً ويستخدم المشروع الجديد في الجذر إذا وُجد.

الطريقة الموصى بها للمستودع الموجود VCCoop-Hamdan1:
1. ثبّت GitHub Desktop وسجّل دخولك، ثم File > Clone repository.
2. اختر gntaz7-pixel/VCCoop-Hamdan1 وافتح المجلد المحلي.
3. فك هذا الملف ZIP في مجلد مؤقت خارج مجلد المستودع.
4. الأسهل: اسحب مجلد المستودع المحلي الذي استنسخته فوق ملف
   1_FIX_EXISTING_GITHUB_REPO.cmd الموجود بجانب src. السكربت ينسخ الملفات
   تلقائياً إلى جذر المستودع، بما فيها المجلد المخفي .github، بدون حذف .git.
   أو انسخ محتويات الحزمة يدوياً إلى جذر المستودع، لا تنسخ مجلدها الأب.
5. من GitHub Desktop اضغط Commit to main ثم Push origin.
6. افتح Actions > Build VCCoop Hamdan DLL (Win32) > Run workflow.
7. إذا ظهرت علامة خضراء، افتح النتيجة وحمّل الملف من Artifacts باسم
   VCCoop-Hamdan-Install-Win32. فك ضغطه أولاً.
8. إذا فشل البناء، افتح سطر الخطأ الأحمر وأرسله لتصحيحه.

بديل أسرع بلا نسخ كل الملفات:
إذا كان مشروعك القديم داخل VCCoop_Hamdan_GitHub_Ready، انسخ فقط
.github/workflows/build-hamdan.yml من حزمة الإصلاح المنفصلة إلى جذر
المستودع (وليس داخل المجلد القديم)؛ الملف يدعم هذا الترتيب أيضاً.

ملحوظة: الملف الذي ستحمّله من Actions هو ناتج بناء جديد وليس DLL مضمونة
العمل. استخدم نسخة احتياطية، وثبّت نفس DLL على الجهازين قبل اختبار السنك.
